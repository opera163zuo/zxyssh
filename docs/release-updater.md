# zxySSH Updater Signing

zxySSH uses the Tauri 2 updater plugin. Release builds produce signed updater
artifacts and a `latest.json` manifest uploaded to GitHub Releases.

## Signing Key

The updater public key is committed in `src-tauri/tauri.conf.json`.

This distribution signs with its **own** keypair, generated at 2.0.1 preparation
time; it is not the key that signed earlier upstream releases. The private key
and its passphrase live outside the repository at:

```text
~/.config/zxyssh/updater/private_key
~/.config/zxyssh/updater/passphrase      # 0600, never committed
```

Keep those files secret and backed up. If they are lost, existing installations
cannot verify future updates signed by a different key unless they first install
a build that contains the new public key. Because no signed artifact had been
published from this repository before the key was introduced, no installed
client depends on the previous key.

## GitHub Secrets

Set both values from the files above:

```bash
gh secret set TAURI_SIGNING_PRIVATE_KEY --repo opera163zuo/zxyssh < ~/.config/zxyssh/updater/private_key
gh secret set TAURI_SIGNING_PRIVATE_KEY_PASSWORD --repo opera163zuo/zxyssh < ~/.config/zxyssh/updater/passphrase
```

This key is password-protected, so `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` is
required. Verify a signing run cryptographically before publishing:

```bash
npx --no-install tauri signer sign --private-key "$(cat ~/.config/zxyssh/updater/private_key)" \
  --password "$(cat ~/.config/zxyssh/updater/passphrase)" /tmp/signing-probe.txt
python3 scripts/verify-updater.py /tmp/signing-probe.txt   # needs the minisign binary
```

Important: empty-password updater keys generated by `@tauri-apps/cli` versions
`2.9.3` through `2.10.0` are broken and will fail in CI with an "incorrect
updater private key password" error. Generate or rotate updater keys with
`@tauri-apps/cli >= 2.10.1`.

## Release Output

The release workflow:

1. Creates or updates the GitHub Release for the new tag.
2. Validates that the updater signing key can sign an artifact before any
   platform builds start.
3. Builds each desktop platform with `TAURI_SIGNING_PRIVATE_KEY`.
4. Uploads updater artifacts and their `.sig` files to the GitHub Release.
5. Generates `latest.json` with platform URLs and signatures.
6. Uploads `latest.json`.

The update manifest is served from:

```text
https://github.com/opera163zuo/zxyssh/releases/latest/download/latest.json
```

The app checks that endpoint and uses Tauri's `downloadAndInstall()` flow for
one-click signed updates.
